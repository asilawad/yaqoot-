Root cause (confirmed)

The backup/export feature is almost certainly implemented using a browser-style download trick — something like creating a Blob, generating an object URL with URL.createObjectURL(), and triggering a click on a hidden <a download="..."> element. This works fine in a normal web browser or in Vite dev mode, but inside a bundled Tauri app running in WebView2, this pattern either silently saves to a default folder or is blocked/ignored by the WebView's security context — there's no "Save As" dialog because this is fundamentally a web download mechanism, not a native file-save mechanism.

The restore/import feature likely works because it uses a plain <input type="file"> element, which is a standard form control that WebView2 handles natively and correctly.
